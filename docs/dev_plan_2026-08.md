## 2. 🔴 핵심 문제 — 편집기에 "구성" 개념이 없다

`video_editor.build_reel()` 의 현재 시그니처:

```python
build_reel(clip_paths, output_path, target_seconds=..., hook=..., menu=..., cta=...)
```

이게 실제로 하는 일:
1. 클립들을 **받은 순서 그대로** 이어붙인다
2. 훅 자막 **1개**를 첫 2.5초에 얹는다
3. 메뉴 자막 1개를 하단에 상시로 깐다
4. 목표 길이로 뒤를 자른다

즉 **샷 단위 연출이 없다.** 어떤 클립을 몇 초 보여줄지, 클립마다 어떤 자막을
깔지, 어떤 순서로 긴장을 쌓을지 — 표현할 방법 자체가 없다.
`templates.py` T1~T5도 길이·페이스·음악무드 4개 값뿐이고, **그나마 T1 고정**이다.

> 잘 짜인 기획안이 있어도 편집기에 **전달할 통로가 없다.**
> 그래서 이번 개발의 1순위는 "기획 자동화"도 "자막 예쁘게"도 아니라
> **기획안을 담을 그릇(샷 구성표)을 만들고 편집기가 그걸 실행하게 하는 것**이다.

## 3. Phase 1 ⭐ 샷 구성표(Shot Plan) — 최우선

### 3-1. 자료구조 신설 `sns_automation/shot_plan.py`

기획안 = 사람이 읽는 글이 아니라 **편집기가 실행하는 명세**로 만든다.

```jsonc
{
  "template": "T2",
  "target_seconds": 22,
  "hook": {                       // 첫 3초 — 이탈 방어
    "text": "송도에서 이건 여기서만",
    "seconds": 2.5,
    "angle": "지역·한정"           // 호기심 / 구체성 / 지역·한정
  },
  "shots": [                      // ← 이게 '구성'. 지금 없는 것
    {"clip": "IMG_6321.mov", "in": 0.0, "out": 3.2,
     "caption": "반죽부터 직접",  "role": "훅샷"},
    {"clip": "IMG_6245.MOV", "in": 1.5, "out": 5.0,
     "caption": "크림치즈 듬뿍",  "role": "핵심"},
    {"clip": "IMG_6244.mov", "in": 0.0, "out": 2.5,
     "caption": null,             "role": "여운"}
  ],
  "cta": {"text": "저장해두고 오세요", "seconds": 2.0}
}
```

### 3-2. 편집기가 구성표를 실행 — `build_reel_from_plan()`

`build_reel()`은 남겨두고(호환) 위에 구성표 실행기를 얹는다.
- 샷별 **in/out 구간 컷** (지금은 클립 통째로 → 앞부분 늘어짐)
- 샷별 **자막 타이밍** (지금은 훅 1개 + 메뉴 1개 고정)
- 샷 **순서·역할** 대로 배치
- 훅 3초 규격 강제 (`role: 훅샷` 이 항상 맨 앞)

### 3-3. 웹에서 구성표를 표로 보고 고친다

`pipeline.html`에 **구성표 편집 화면** 추가:
- 샷 목록 = 표. 클립 썸네일 / 구간 / 자막 / 역할
- 순서 바꾸기, 자막 수정, 샷 빼기
- **[이대로 편집]** → 렌더

이러면 "기획안 → 편집"이 끊기지 않고 한 줄로 이어진다.
지금 끊겨 있는 `caption_generator.overlay_text` → 자막 수동 입력 문제도 함께 해소.

### 3-4. 템플릿을 구성 패턴으로 승격

T1~T5를 "길이·무드 4값"에서 **샷 구성 뼈대**로 바꾼다.
예) T2 신메뉴 = `훅샷(3s) → 클로즈업(4s) → 단면/리액션(5s) → 정보자막(4s) → CTA(2s)`
기획 AI는 이 뼈대에 실제 클립을 배치하기만 하면 된다. 품질이 안정된다.

## 4. Phase 2 — 기획 AI가 구성표를 생성

Phase 1의 그릇이 생긴 다음. 순서가 바뀌면 안 된다.

1. **LLM 계층 이식** — 비서 프로젝트 `llm.py`(Gemini 폴백)를 SNS로 가져온다.
   현재 SNS의 Anthropic 키는 무효(401)라 캡션·기획이 전부 폴백만 나온다.
   `GEMINI_API_KEY` 복사만으로 즉시 살아난다. **크레딧 충전 불필요.**
2. **`planner.plan_shots()`** — 입력: 주제 + 클립 목록(길이·미리보기 프레임) +
   `knowledge/`(브랜드 톤·금지표현) + 훅 성과 기록 → 출력: §3-1 구성표 JSON.
3. **훅 3버전**을 구성표 단위로 확장 — 지금은 훅 문구 3개만.
   앞으로는 **훅이 바뀌면 앞 샷 구성도 같이 바뀐 3안**을 낸다. 진짜 A/B가 된다.

## 6. Phase 4 — 접근성 (직원용 웹앱 통합)

사장님이 희망한 PythonAnywhere 통합. **편집 축을 먼저 세운 뒤**에 한다.

주의: **PA에서 ffmpeg 렌더는 못 돌린다** (CPU초·디스크 제한).
비서 프로젝트가 이미 쓰는 구조를 그대로 재사용한다.

```
[폰] ──▶ PA 직원웹 "SNS" 탭 (업로드·구성표 확인·검수)
              ▼  Supabase jobs 큐 (kind='reel_render')
        집 PC worker/agent.py  ── ffmpeg ──▶ 완성본 mp4
              ▼  Supabase Storage 공개 URL
        폰에서 다운로드 → Edits 앱에서 인기음원 얹어 발행
```

**대안(가벼움):** 부담되면 현행 집 PC 웹앱 + 폰 와이파이 접속으로 버틴다.
이미 구현돼 있다(커밋 `e0082fc`).

## 8. 지금 당장 할 수 있는 것 (Phase 0)

편집이 가장 중요하니, **현재 편집기가 실제 매장 영상으로 뭘 뱉는지 먼저 본다.**
드라이브에 실제 영상이 있는 게 확인됐으므로 **개발 없이 지금 렌더 가능**하다.

1. 드라이브 커넥터로 매장 클립 2~3개를 가져온다
2. 현재 `build_reel`로 릴스 1개를 뽑는다
3. 사장님이 보고 **"뭐가 부족한지"** 를 말한다
   → 이게 Phase 1의 샷 구성표·자막 스펙을 확정하는 근거가 된다

추측으로 튜닝하지 않는다. 실물을 보고 정한다.
