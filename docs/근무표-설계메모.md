### 이 화면만 자바스크립트로 그리는 이유

다른 화면들은 폼 제출 + 서버 렌더가 관례인데, 주간 캘린더는 **끌어서 옮기는 조작**이
핵심이라 그 방식으로는 안 된다(한 번 끌 때마다 페이지가 새로 뜬다).
그래서 서버가 데이터를 JSON 으로 한 번 넘겨주고, 화면은 자바스크립트가 그리며,
바뀐 건 `fetch` 로 자동 저장한다. 외부 라이브러리는 여전히 안 쓴다.

## 왜 만드나 (노션 DB의 문제)

지금은 노션 DB를 캘린더 뷰로 쓰고, 월이 바뀌면 Markdown으로 받아 급여명세서
프로그램에 넣는다. 불편한 점:

- 점점 무거워짐
- 노션 계정 없으면 직원이 못 봄
- 폰에서 보기 불편
- 수정을 하나하나 해야 함

## 핵심 개념: 예정 / 확정 / 실제

| 상태 | 뜻 | 색(기존 웹앱 토큰) |
|---|---|---|
| 예정 | 미리 짜둔 스케줄. 아직 바뀔 수 있음 | `--warn` 갈색 "작성 중" |
| 확정 | 이 주는 더 이상 안 바꾼다고 잠근 상태 | `--accent` 파랑 🔒 |
| 실제 | 실제로 근무한 시간. 지각·연장으로 달라질 수 있음 | `--ok` 초록 ✓ / 다르면 `--warn` |

**확정은 주 단위로 잠근다.** 잠그면 편집 버튼 자체가 사라지고, 직원 화면에도
"확정"으로 뜬다 — 직원이 "이제 안 바뀌니 약속 잡아도 된다"고 믿을 수 있게 하는 게
이 기능의 진짜 목적.

**실제는 예외만 입력한다.** 지나간 날은 변동이 없으면 자동으로 "예정대로" 처리.
지각·연장·조퇴·결근만 손으로 고친다. 이러면 평소엔 아무도 아무것도 안 눌러도 된다.
대신 기록 누락이 곧 급여 오차이므로, 마감 SOP 마지막에 "근무 변동 있었으면 기록"
한 줄을 넣어 방어한다.

## 영업시간 ≠ 근무시간

근무 시간표는 **영업시간보다 앞뒤로 넓다.** 오픈 근무자는 영업 시작 전에 출근하고,
마감 근무자는 영업 종료 후에 퇴근하기 때문.

예) 영업 07:00–21:00 → 오픈조 06:30 출근, 마감조 21:30 퇴근

그래서 주간 캘린더의 시간축은 **영업시간과 실제 근무시간을 모두 감싸도록 자동 계산**한다
(`min(영업시작, 가장 이른 출근)` ~ `max(영업종료, 가장 늦은 퇴근)`). 영업시간 밖 구간은
빗금으로 칠해 "매장은 닫혀 있지만 근무 중"인 준비·마감 시간임을 한눈에 보이게 한다.

## 주간 화면은 캘린더(시간축 위클리 뷰)

가로 = 월~일 7일, 세로 = 시간축. 근무가 시간 위치에 블록으로 놓여서 **커버 구멍과
겹침이 눈에 바로 보인다.** 겹치는 근무는 세로줄을 나눠 나란히 배치(일반 캘린더와 같은 규칙).
빈 곳을 누르면 그 시간에 근무 추가.

직원용 화면은 기본이 **요일별 목록**(폰에서 읽기 쉬움)이고, 원하면 같은 주를
캘린더로도 볼 수 있다. 캘린더에서는 자기 근무만 진하게, 남의 근무는 흐리게 나온다.

## 지금 쓰는 구글시트(스타벅스식 양식)에서 가져온 것

사장님이 쓰는 시트는 **요일별 탭 7개**, 각 탭이 하루치 근무시간표다.
행 = 근무자, 가로 = 30분 단위 시간축. 스타벅스 리테일 스케줄 양식을 번안한 것.
가져올 만한 구조:

| 시트에 있던 것 | 웹에서 |
|---|---|
| `포지션 / 근무자 / WT / 출근시간 / 퇴근시간` 컬럼 | 데일리 화면에 그대로 |
| `WT` = 퇴근 − 출근 − 휴게 | 자동 계산 (시트에선 손계산이라 오차가 있었음) |
| 격자 위 한 글자 `B`(30분) `M`(1시간) 휴게 | 근무 막대 위 흰 칸으로 표시 |
| 표 위 `시간대별 인원` 행 | 자동 계산 — **영업 중 0명 구간을 빨갛게 경고** |
| `D9` 그날 총 근무시간 | WT 합계 자동 |
| `매장영업시간` vs `매장근무시간` 을 따로 적음 | 영업시간 ≠ 근무시간 (아래 참고) |
| 포지션 약어 `P`(포스) `B`(바) `S`(제조) `SP`(서포터) | 아직 미반영 — 넣을지 결정 필요 |

시트에서 발견한 문제(웹으로 옮기면 자동으로 사라지는 것):
- `D9` 합계 수식이 화~금 탭에서 `V1`로 깨져 있었다
- 일요일 마감 근무 `WT`가 실제보다 30분 많다 (손계산 오차)
- 근무 구간이 **색칠**과 **출/퇴근 시각** 두 곳에 이중으로 들어가 어긋날 수 있다
- 코드 범례에서 `B`가 "30분휴식"과 "Bar" 두 뜻으로 겹친다

시트 아래 절반(인수인계·서명, 급해요, 전달사항, 품절현황, 예약주문)은 근무표가 아니라
**당일 운영 보드**다. 근무표와 분리해서 따로 다룰지 정해야 한다.

**아직 안 넣은 것: 요일별 영업시간.** 시트를 보면 요일마다 영업시간이 다르다
(월 07:30–22:00, 수·목·금 07:30–23:00, 일 07:30–21:00). 지금 목업은 매장 영업시간이
하나뿐이라, 요일별로 나눠야 한다.

## 데일리 근무표는 인쇄해서 매장에 붙인다

**A4 가로 한 장.** 인쇄하면 앱 메뉴·탭·마감 기록 버튼은 다 빠지고 이것만 나온다:

1. 머리말 — 매장명, 날짜, 매장영업시간, 매장근무시간, 총 근무시간, 인원, 날씨
2. 시간대별 **예상 매출** 막대그래프
3. 시간대별 **실제 근무 인원** 막대그래프 (매출 대비 부족하면 주황, 0명이면 빨강)
4. 근무표 (포지션·근무자·WT·출근·퇴근·30분 격자)
5. 인수인계 · 확인 서명 · 전달사항 칸 — 시트에 있던 걸 그대로 옮김

두 그래프와 근무표는 **시간축이 픽셀 단위로 맞춰져 있다.** 위에서 매출이 솟은 자리를
그대로 아래로 내려보면 그 시간에 누가 있는지가 보인다. 이게 이 종이의 존재 이유다.

### 예상 매출은 무엇을 기준으로 하나

**최근 4주, 같은 요일, 30분 단위 매출의 중앙값**을 기본으로 잡았다.

- **평균이 아니라 중앙값** — 단체주문(삼성바이오·인천대 같은) 한 번에 그래프가 통째로
  휘는 걸 막는다. 시트를 보니 실제로 그런 주문이 있었다.
- **작년 데이터를 안 쓰는 이유** — 매장이 오픈 10개월차라, 작년 이맘때는 지금과 손님
  수가 다르다. 1년쯤 더 쌓이면 "작년 같은 주" 비교를 옆에 겹쳐 보여줄 만하다.
- **연평균·월평균을 안 쓰는 이유** — 요일 차이를 뭉갠다. 평일과 주말 곡선이 완전히 다르다.
- **4주인 이유** — 최근 흐름을 담으면서 같은 요일 표본을 4개 확보한다.
- 휴무일·공휴일은 표본에서 빼고, **공휴일은 지난 공휴일들만 따로 모아** 본다
  (공휴일은 주말처럼 움직인다).
- 계산은 POS 매출 내역에서 **하루 한 번** 돌려 파일로 저장한다.

**인원 부족 판단**: `필요 인원 = 올림(그 30분 예상매출 ÷ 1인이 감당하는 매출)`.
1인 기준값은 설정에서 바꿀 수 있다(목업 기본 30분당 3.5만원). 실제 값은 사장님이
바쁜 날 체감으로 몇 번 조정해보면 맞춰진다.

## 영업시간은 "언제부터 이랬다"를 쌓는다 (과거를 건드리지 않기)

영업시간을 설정값 하나로 두면, 나중에 바꿀 때마다 **과거 근무표까지 새 영업시간으로
다시 그려진다.** 작년 이맘때 21시에 닫던 날이 23시에 닫은 것처럼 보이게 된다.

그래서 영업시간은 값 하나가 아니라 **적용 시작일이 붙은 기록의 목록**으로 둔다:

```
2026-01-01 부터 → 매일 07:00–21:00
2026-09-02 부터 → 월·화·목·금·토·일 07:00–21:00 / 수 07:00–23:00
```

어떤 날의 영업시간 = 그 날짜 이전의 마지막 기록. 바꿔도 그 이전 날짜는 그대로다.
요일별로 다르게 넣을 수 있다(시트를 보니 수·목·금은 23시까지였다).

**근무 기록 자체는 애초에 영향을 안 받는다.** 출근·퇴근 시각은 그 자체로 저장되는
데이터라, 영업시간은 화면의 배경(음영·점선)과 "영업 몇 분 전 출근" 같은 계산에만 쓰인다.
영업시간을 아무리 바꿔도 이미 기록한 근무 시각과 WT는 변하지 않는다.

같은 원리를 나중에 시급에도 쓴다 — 시급 인상도 "언제부터"가 붙어야 지난달 급여가 안 바뀐다.

## 매장 휴무 · 공휴일 · 날씨

- **휴무**: 정기 휴무 요일 + 임시 휴무 날짜. 휴무일은 캘린더에서 빗금 처리되고 근무를
  넣을 수 없다. 이미 근무가 있으면 지워도 되는지 먼저 묻는다.
- **공휴일**: 한국천문연구원 특일 정보 API(공공데이터포털, 무료). **1년에 한 번** 받아
  파일로 저장. 빨간날은 날짜 밑에 이름이 뜨고, 그 주 상단에 "공휴일이 있어요" 안내가 뜬다.
- **날씨**: 기상청 단기예보 API(공공데이터포털, 무료). **하루 한 번 새벽에** 받아 파일로
  저장하고, 지난 날짜는 그때 받아둔 값을 그대로 보관한다(화면 열 때마다 호출 안 함).
  카페는 비 오는 날 손님이 줄어 인력 조정이 필요하고, 나중에 "그날 비가 와서 한가했다"를
  근무 기록과 같이 볼 수 있다.
  - ⚠️ Open-Meteo는 무료지만 **비상업용 전용**이라 매장 운영에는 쓰지 않는다.
  - 호출량: 공휴일 연 12회 + 날씨 하루 1~2회 = 사실상 비용 0.

## 접근 권한 — 두 개의 화면

**직원용 링크** (`/s/<토큰>` 같은 공개 경로, 로그인 없음)
- 주간/데일리 스케줄 **열람만**
- 사이드바를 아예 렌더하지 않음 → 회의기록·MKT캘린더 등 다른 프로그램 접근 불가
- 단톡방에 링크 한 번 공유하면 끝. 노션 계정 불필요

**관리자 화면** (`/schedule`, 기존 로그인 뒤)
- 스케줄 작성·확정·실제 기록·데이터 내보내기
- 기존 웹앱 사이드바에 "🕒 근무표" 한 줄 추가

## 급여는 이 페이지에서 계산하지 않는다

급여는 관리자도 아닌 **사장만** 보는 정보다. 그래서 페이지에는 시급·금액이
**아예 없다.** 대신 실제 근무 데이터를 별도 프로그램에 넣기 좋은 형태로 뽑아주기만
한다 (Markdown / CSV). 지금 노션에서 월말에 다운받던 그 자리를 이 버튼이 대신한다.

내보내는 표: `날짜 | 이름 | 예정 | 실제 | 시간 | 비고(지각·연장·결근)` + 사람별 합계

**기간은 직접 고른다.** 월 단위 고정이 아니라 시작일~종료일을 지정하고, 자주 쓰는 기간
(이번 달 / 지난달 / 이번 주 / 지난주 / 전반 1~15일 / 후반 16일~)은 버튼 한 번.
급여 마감 주기가 바뀌어도 그대로 쓸 수 있다.

## 스케줄 짜기를 빠르게 하는 장치

1. **지난주 복사** — 버튼 한 번. 매주 거의 같으므로 이게 반복 입력의 대부분을 없앤다
2. **근무 시간대** — 오픈/미들/마감 버튼 한 번이면 시간이 채워짐 (시간 타이핑 없음)
3. **드래그로 옮기기** — 근무 블록을 끌어 다른 요일·시간으로 옮기고, 위아래 끝을 끌어 시간을 늘리고 줄인다

- 직원 명단 (목업은 지은·민수·하늘·소연·준호 가상 이름)

  `5_웹파이프라인.bat`이 돌 때만 산다. PC가 꺼지면 직원이 근무표를 못 본다.

## 구현 시 따를 관례

기존 웹앱 그대로: Flask + Jinja 서버 렌더, form POST 저장, 파일 기반 데이터(YAML/JSON),
외부 JS 라이브러리 없음. 규모가 크므로 `webapp/schedule.py` 블루프린트로 분리
(인스타 파이프라인과 같은 방식). 색·카드·버튼은 `base.html`의 기존 토큰 재사용.

캘린더 블록의 위치 계산(`top = (시작시각 − 축시작) × 시간당픽셀`)과 겹침 세로줄 배치는
목업에서는 JS로 했지만, **실제 구현에서는 파이썬에서 계산해 Jinja로 넘긴다** — 기존
`/calendar` 화면이 파이썬 `calendar` 모듈로 주 배열을 만들어 넘기는 것과 같은 방식.
