# 근무 스케줄 페이지 — 설계 메모

목업: [docs/mockups/근무표-목업.html](mockups/근무표-목업.html) (브라우저로 열면 눌러볼 수 있음)

2026-08-30 목업 단계. 아직 구현 전 — 사장님 피드백 후 확정한다.

## 왜 만드나 (노션 DB의 문제)

지금은 노션 DB를 캘린더 뷰로 쓰고, 월이 바뀌면 Markdown으로 받아 급여명세서
프로그램에 넣는다. 불편한 점:

- 점점 무거워짐
- 노션 계정 없으면 직원이 못 봄
- 폰에서 보기 불편
- 수정을 하나하나 해야 함

## 핵심 개념: 예정 / 확정 / 실제

| 상태 | 뜻 | 색(기존 웹앱 토큰) |
|---|---|---|
| 예정 | 미리 짜둔 스케줄. 아직 바뀔 수 있음 | `--warn` 갈색 "작성 중" |
| 확정 | 이 주는 더 이상 안 바꾼다고 잠근 상태 | `--accent` 파랑 🔒 |
| 실제 | 실제로 근무한 시간. 지각·연장으로 달라질 수 있음 | `--ok` 초록 ✓ / 다르면 `--warn` |

**확정은 주 단위로 잠근다.** 잠그면 편집 버튼 자체가 사라지고, 직원 화면에도
"확정"으로 뜬다 — 직원이 "이제 안 바뀌니 약속 잡아도 된다"고 믿을 수 있게 하는 게
이 기능의 진짜 목적.

**실제는 예외만 입력한다.** 지나간 날은 변동이 없으면 자동으로 "예정대로" 처리.
지각·연장·조퇴·결근만 손으로 고친다. 이러면 평소엔 아무도 아무것도 안 눌러도 된다.
대신 기록 누락이 곧 급여 오차이므로, 마감 SOP 마지막에 "근무 변동 있었으면 기록"
한 줄을 넣어 방어한다.

## 영업시간 ≠ 근무시간

근무 시간표는 **영업시간보다 앞뒤로 넓다.** 오픈 근무자는 영업 시작 전에 출근하고,
마감 근무자는 영업 종료 후에 퇴근하기 때문.

예) 영업 07:00–21:00 → 오픈조 06:30 출근, 마감조 21:30 퇴근

그래서 주간 캘린더의 시간축은 **영업시간과 실제 근무시간을 모두 감싸도록 자동 계산**한다
(`min(영업시작, 가장 이른 출근)` ~ `max(영업종료, 가장 늦은 퇴근)`). 영업시간 밖 구간은
빗금으로 칠해 "매장은 닫혀 있지만 근무 중"인 준비·마감 시간임을 한눈에 보이게 한다.

## 주간 화면은 캘린더(시간축 위클리 뷰)

가로 = 월~일 7일, 세로 = 시간축. 근무가 시간 위치에 블록으로 놓여서 **커버 구멍과
겹침이 눈에 바로 보인다.** 겹치는 근무는 세로줄을 나눠 나란히 배치(일반 캘린더와 같은 규칙).
빈 곳을 누르면 그 시간에 근무 추가.

직원용 화면은 기본이 **요일별 목록**(폰에서 읽기 쉬움)이고, 원하면 같은 주를
캘린더로도 볼 수 있다. 캘린더에서는 자기 근무만 진하게, 남의 근무는 흐리게 나온다.

## 접근 권한 — 두 개의 화면

**직원용 링크** (`/s/<토큰>` 같은 공개 경로, 로그인 없음)
- 주간/데일리 스케줄 **열람만**
- 사이드바를 아예 렌더하지 않음 → 회의기록·MKT캘린더 등 다른 프로그램 접근 불가
- 단톡방에 링크 한 번 공유하면 끝. 노션 계정 불필요

**관리자 화면** (`/schedule`, 기존 로그인 뒤)
- 스케줄 작성·확정·실제 기록·데이터 내보내기
- 기존 웹앱 사이드바에 "🕒 근무표" 한 줄 추가

## 급여는 이 페이지에서 계산하지 않는다

급여는 관리자도 아닌 **사장만** 보는 정보다. 그래서 페이지에는 시급·금액이
**아예 없다.** 대신 실제 근무 데이터를 별도 프로그램에 넣기 좋은 형태로 뽑아주기만
한다 (Markdown / CSV). 지금 노션에서 월말에 다운받던 그 자리를 이 버튼이 대신한다.

내보내는 표: `날짜 | 이름 | 예정 | 실제 | 시간 | 비고(지각·연장·결근)` + 사람별 합계

**기간은 직접 고른다.** 월 단위 고정이 아니라 시작일~종료일을 지정하고, 자주 쓰는 기간
(이번 달 / 지난달 / 이번 주 / 지난주 / 전반 1~15일 / 후반 16일~)은 버튼 한 번.
급여 마감 주기가 바뀌어도 그대로 쓸 수 있다.

## 스케줄 짜기를 빠르게 하는 장치

1. **지난주 복사** — 버튼 한 번. 매주 거의 같으므로 이게 반복 입력의 대부분을 없앤다
2. **시프트 프리셋** — 오픈/미들/마감 버튼 한 번이면 시간이 채워짐 (시간 타이핑 없음)
3. **직원별 기본 패턴** — 빈 칸만 자동으로 채움

## 아직 정해야 할 것

- 매장 영업시간 (리포 `knowledge/` 전부 플레이스홀더 상태 — 목업은 07:00–21:00 예시)
- 오픈 준비 / 마감 정리 시간 (목업은 앞뒤 각 30분)
- 시프트 프리셋 시간 (목업은 오픈 06:30–12:00 / 미들 10–15 / 오후 14–19 / 마감 16:00–21:30)
- 직원 명단 (목업은 지은·민수·하늘·소연·준호 가상 이름)
- **직원용 링크를 외부에서 열 수 있게 할 방법** — 지금 웹앱은 집 PC에서
  `5_웹파이프라인.bat`이 돌 때만 산다. PC가 꺼지면 직원이 근무표를 못 본다.
  노션은 항상 열렸으므로 이건 후퇴 지점이다. 구현 전에 결정 필요
- 개인정보(직원 실명·근무시간)가 들어가므로 데이터 파일은 `.gitignore` 대상

## 구현 시 따를 관례

기존 웹앱 그대로: Flask + Jinja 서버 렌더, form POST 저장, 파일 기반 데이터(YAML/JSON),
외부 JS 라이브러리 없음. 규모가 크므로 `webapp/schedule.py` 블루프린트로 분리
(인스타 파이프라인과 같은 방식). 색·카드·버튼은 `base.html`의 기존 토큰 재사용.

캘린더 블록의 위치 계산(`top = (시작시각 − 축시작) × 시간당픽셀`)과 겹침 세로줄 배치는
목업에서는 JS로 했지만, **실제 구현에서는 파이썬에서 계산해 Jinja로 넘긴다** — 기존
`/calendar` 화면이 파이썬 `calendar` 모듈로 주 배열을 만들어 넘기는 것과 같은 방식.
